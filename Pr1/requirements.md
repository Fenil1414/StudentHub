# StudentHub — Requirement Analysis

## 1. Project Overview

StudentHub is a web-based student portal designed to provide students with important academic and campus-related information in one place. The portal will allow students to access their profile, subjects, timetable, attendance, assignments, notices, study materials, faculty information, and upcoming events.

## 2. Problem Statement

Students often need to check information from different sources such as notices, timetables, assignment details, attendance records, and study materials. StudentHub aims to provide a single, organized platform where students can easily access this information.

## 3. Project Objectives

* Provide a centralized student portal.
* Make academic information easily accessible.
* Provide simple and clear navigation.
* Display assignments and important deadlines.
* Provide timetable and attendance information.
* Display notices and upcoming events.
* Organize study materials in one place.

## 4. User Roles

### Student

* Login to the portal.
* View and update profile information.
* View subjects and timetable.
* Check attendance.
* View assignments and deadlines.
* Read notices.
* Access study materials.
* View faculty and events information.

### Faculty

* Manage subject information.
* Add and manage assignments.
* Publish notices.
* Upload study materials.
* View relevant student information.

### Admin

* Manage students and faculty.
* Manage portal content.
* Manage notices and events.
* Manage subjects and other system information.

1. Login
2. Dashboard

10. Events

## 6. Functional Requirements

* The system shall provide a login page.
* The system shall display a dashboard after login.
* Students shall be able to view their profile.
* Students shall be able to view their subjects.
* Students shall be able to view their timetable.
* Students shall be able to view attendance information.
* Students shall be able to view assignments and deadlines.
* Users shall be able to view notices.
* Students shall be able to access study materials.
* Users shall be able to view upcoming events.
* Students shall be able to view faculty information.
* Users shall be able to access the Contact / Help page.

## 7. Non-Functional Requirements

* The website should have a simple and user-friendly interface.
* The website should be responsive on different screen sizes.
* Pages should load quickly.
* Navigation should be consistent across pages.
* The project should have a properly organized folder structure.
* The source code should be maintained using Git and GitHub.

## 8. Expected Outcome

The final StudentHub portal will provide students with a centralized and organized platform for accessing academic and campus-related information.
